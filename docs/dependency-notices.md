# Distributed dependency notices

Run `npm run build`, open Support in the release application, and follow Dependency notices. The page is also served at `/notices/index.html` (for example, `http://localhost:4173/notices/index.html` after `npm run preview`). The readable index links exact publisher text copies and `inventory.json`. Its relative links work under the served application base. The existing production service worker precaches the index, inventory and full text copies for offline access; the build verifies their precache inclusion and byte hashes.

The source record is [third-party/inventory.json](../third-party/inventory.json), with exact copies in [third-party/notices](../third-party/notices). Every resolved production package and emitted Workbox package has its installed version, package source/integrity and text hashes. The bundler records the emitted browser/font/WASM asset filenames. Worker-runtime entries identify the generated `workbox-*.js` relationship; the final build checks the actual worker's package markers against the inventory. Workbox's embedded marker says7.4.0 while installed metadata says7.4.1; these are recorded separately.

The record also preserves positively identified upstream material embedded inside packages: Alea in ts-fsrs, Safari IndexedDB and tslib helpers in Dexie, SQL.js AUTHORS, SQLite's original source disclaimer, and Emscripten's selected runtime publication (including its Node-path and musl material). Installed code/map/WASM hashes guard those recorded source relationships. Publisher references and hashes distinguish exact retained texts from assumptions about compilation.

The production browser test compares every served notice with its publisher hash in both browser projects. Chromium additionally verifies a fresh offline document served by the installed service worker and exact offline fetch delivery. Phone-sized WebKit verifies exact retained native CacheStorage bytes in the existing document; its offline reload and fetch controls failed with browser errors, while the revision-aware cache control passed. Cache retention does not establish WebKit service-worker delivery or installed-iPhone cold opening. Those limits remain documented in [offline verification](offline-verification.md).

The build refuses a missing or changed required text, changed installed source, new production package, or stale version/integrity inventory. `npm run test:notices` exercises missing-text, modified-text and stale-version failures using copies of the actual current inventory and installed source files. Both normal push and complete gates include these checks. Review new publisher sources and shipped asset relationships when updating a dependency; do not merely recalculate hashes to silence a failure. Notice copies disable Git newline conversion so the retained bytes remain exact across platforms.

## Unresolved provenance

Ankipack0.3.1's installed/root/proto MIT statements coexist with GNU AGPLv3-or-later attribution in its generated Anki files. Both are retained, and their provenance remains unresolved. The bundle does not choose a combined licence or grant AnkiWeb account permission.

SQL.js1.12.0's release source selects Emscripten3.1.64, while installed WASM publicly reports SQLite3.45.2. This does not provide a reproducible compiler/link-map attestation for every installed runtime object. Its build also fetches SQLite contrib extension-functions.c separately from core. The current contributor source and attribution are preserved with their hash; historical installed-input identity and its licence remain unverified. The extension is not labelled SQLite public domain. The full Emscripten/musl publication texts preserve their attribution catalogue without asserting every listed compiler component is shipped.

These are technical preservation records. They do not supply a project licence grant, resolve [#184's deferred criteria](https://github.com/butahlecoq/anki/issues/184), or establish [#1 story65's complete free/open-source requirement](https://github.com/butahlecoq/anki/issues/1). Existing application, account, exchange and private-service behavior is unchanged; this feature adds static public notice assets only.
