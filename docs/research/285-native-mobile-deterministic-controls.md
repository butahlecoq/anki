## Smallest supported measurement change

The precise seam is `tests/e2e/statistics-date-labels.spec.ts`, inside the `[320, 390]` loop, immediately after its viewport observation: `for (const button of await heatmap.getByRole('button').all())` and each `button.boundingBox()`. The product emits 84 keyed date buttons in `src/Statistics.tsx` from `reviewHeatmap(entries, now)`; `src/progress-statistics.ts` defaults that projection to 84 days. See the [fixed-source test](https://github.com/butahlecoq/anki/blob/e32e7905ab4ae872b736eab0abe687d553118d56/tests/e2e/statistics-date-labels.spec.ts) and [rendered projection](https://github.com/butahlecoq/anki/blob/e32e7905ab4ae872b736eab0abe687d553118d56/src/Statistics.tsx).

`locator.evaluateAll` executes one callback with every matched element. `locator.all()` instead snapshots currently matched locators without waiting for a changing list to finish loading. These are supported public APIs. [Playwright Locator documentation](https://playwright.dev/docs/api/class-locator#locator-evaluate-all), [list readiness](https://playwright.dev/docs/api/class-locator#locator-all).

Proposed implementation, still untested: assert the exact 84-button count before measurement; batch-read every button's accessible label, `time[datetime]`, rendered client rectangles, computed visibility and bounding width/height with the same role locator. Return all records, including hidden or zero-size records, and apply the original separate `>=43.99` width and height assertions to every record. Assert 84 distinct expected consecutive dates and preserve diagnostic labels. No `.filter()` may discard a failed, hidden or missing cell. Keep every later scroll, month/day visibility, screenshot, normal click, pressed state, Date/Period value, theme, background distinction and contrast assertion unchanged.

The measurements are main-frame buttons. `boundingBox()` returns null for an invisible element and main-frame viewport-relative coordinates; DOM rectangle reads must preserve that rejection rather than treating a hidden element's dimensions as sufficient. Validate equivalence before replacing the loop. [Playwright bounding boxes](https://playwright.dev/docs/api/class-locator#locator-bounding-box).

For `mobile-design-audit.spec.ts`'s nested `capture(name)`, another narrow seam is its observation evaluation followed by a second evaluation of the same root/scroll widths. Return root width and scroll width once and use those exact values for both the retained JSON and unchanged overflow assertion. Likewise batch-read originalScroll, maximumScroll and step before segmented capture. Return actual scrollY from each existing two-animation-frame scroll evaluation and assert it using the unchanged tolerance. Preserve every segment screenshot, animation-frame wait, iframe readiness/fonts check, screenshot timeout and original scroll restoration. This removes redundant reads without shortening the observable route journey. [Supported page evaluation](https://playwright.dev/docs/api/class-page#page-evaluate).

## Separate pointer readiness control

Faster measurements alone do not cover the Statistics failure. A candidate control must retain the original exact locator and normal native `click()`: scroll its element to the center using the same instant DOM-scroll operation already present in these journeys, then observe actual viewport geometry and `document.elementFromPoint` at its center. Require a positive-size visible target in the actual canvas, outside fixed navigation, with the hit element equal to or descended from the intended control. Record heading, target bounds, navigation bounds and hit target. Wait for this predicate within existing assertion defaults and the original enclosing deadline; do not catch and retry the journey or replace its click with dispatched events. Immediately retain/assert the expected deck-detail or custom-review destination before dependent actions.

This is an inferred experimental control, not a proven historical cause. Playwright normally checks uniqueness, visibility, stability, event reception and enabled state for click. An intercepted point fails event reception; `force` bypasses that protection and is unsuitable. `scrollIntoViewIfNeeded` alone does not check event reception. [Official actionability table and hit targeting](https://playwright.dev/docs/actionability). A supported `expect.poll` can observe the read-only predicate with existing configured assertion timing; it is not permission to increase the original 30/120/60-second test deadlines. [Official polling assertions](https://playwright.dev/docs/test-assertions#expectpoll).

The custom-study button also needs the normal locator to become visible before geometry observation, because its preceding Create session operation updates the rendered list asynchronously. Do not cache an element handle across that update. Retain ordinary app storage, public sample/import setup, default motion, actual host-scale compensation and Safari/touch configuration. These changes do not require product CSS, storage substitutions or an ADR change.

## Falsifiable verification before acceptance

1. In a separate synthetic native DOM control, compare old per-button visible bounding-box width/height with batched records for the same full 84-element set at both actual widths. Include hidden, zero-size, 43px and missing/duplicated-date negative cases; the proposed validation must reject them. This tests preserved observation, not app mocks.
2. Verify the pointer predicate rejects a real covering element in an isolated DOM fixture. In the actual synthetic sample journey, record intended pointer/click target and the public destination. A completed click followed by the wrong destination is a failure, never a successful fallback.
3. Archive the unchanged original source and first artifacts before changing the two test measurement/control seams. Compare assertion inventories and all captured route/segment names. Native traces should show two batched heatmap reads instead of 168 attached-selector waits while all 168 per-button measurements and their 336 width/height assertions still execute. Save exact command/head, terminal result and native lifecycle attribution.
4. Run all three complete supported original journeys with these narrow controls, one Windows iPhone-WebKit worker, zero retries and unchanged deadlines; retain ten repeats per journey, every assertion and capture. Then run the literal complete local gate and hosted gate at the final head and obtain fresh independent Standards/Spec reviews. No broad case filtering or accepting retries as repair evidence.

The concrete next path is therefore a test measurement optimization plus an independently verified pointer-readiness control, followed by all retained journeys. Neither is implemented or verified by this note. If the actual pointer control cannot demonstrate delivery and the expected destination within the original deadline, AC-02 remains unproven; passing batched date measurements cannot substitute for it. The incomplete historical date tail remains a permanent limit even if a supported current deterministic control qualifies. Physical installed-iPhone behavior remains separate.

## Post-rebase Deck capture readiness

After rebasing on merged main `50947cd`, the combined test-only candidate `ed33186` passed all 30 original native test bodies in 12.8m, one worker and zero retries. Every date trace retained two full 84-cell reads and 336 dimension assertions; every measured scroll endpoint and restoration was retained. These passes did not qualify the captures: visual inspection found `10-deck-detail.png` showing “Loading local deck” and the corresponding public geometry observation lacked Study now in five of ten complete audits. The other five observed the Study control. All 714 first-run artifacts and source were archived and hash-verified; hosted run38105786946 was cancelled as obsolete, and the complete local gate was blocked before startup.

The original capture waits for fonts, frames and five animation frames after an earlier heading assertion. Those preparation steps do not establish that the intended Deck view remains ready at the actual observation boundary. Adding an assertion that the same observed controls include Study now reproduced the defect in the entire original audit: one failure and two passes in 2.2m, with unchanged 120s journey and 10s screenshot deadlines, one worker and zero retries. This is a direct application-journey regression, without response mocks or artificial application state. Its failure source, video, native trace and complete report are preserved separately.

The correction waits for the public Study now control after the original font/frame preparation and before measuring the Deck-detail view. The new assertion remains on the actual returned observation, so an incomplete view cannot silently qualify. All original measurements, screenshot definitions, dynamic segment endpoints, scroll restoration, actions, deadlines and retries remain. No product behavior, fixed sleep, forced click or collection access was introduced.

Pending query revalidation, incomplete navigation and a wrong captured view were considered. `DeckDetail` intentionally shows a pending status until its workspace, summary and due queue exist; the existing `deck-readiness.test.tsx` exercises that valid state. The capture evidence proves a test readiness gap, not the underlying timing cause or a production scheduling defect. Historical screenshot counts of49/50 are not an invariant of a different document height, but filenames and endpoints alone also do not prove that the intended content was captured. Qualification requires the original root definitions, every current measured endpoint, the Study control in the actual Deck observation, visual inspection, final native repeats, full local/hosted gates and fresh independent reviews.
